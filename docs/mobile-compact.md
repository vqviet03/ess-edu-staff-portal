# Compact mobile views

Reference: Figma hMW5mNJ72c3prP6xe93fT9, frames 3:374 (students), 4:27 (staff), 4:90 (filters), 3:557 / 4:267 (schedule), 7:118 (tree file rows). Existing navigation and branding stay in place. Desktop changes are limited to the schedule viewer and compact tree file rows. The mobile boundary follows the existing staff-list breakpoint, below MUI `md` (900px).

- Overview, management lists, teacher class list and material library: filters open in a compact mobile dialog. Search stays available. Filter changes remain local until Apply; closing cancels them and Reset clears the draft. Desktop keeps the existing inline controls and immediate updates.
- Management student/staff/profile lists: compact identity rows, 36px avatar, name, ID/status and chevron. The row is a real link to the existing profile URL. Selection is a separate checkbox; selecting never navigates. Create and secondary actions use accessible icon buttons/menu on mobile, while bulk actions expand only when requested or when a selection exists. All existing bulk, export, pagination and route-state functionality remains available.
- Class student roster: mobile identity rows replace horizontal table scrolling. Name/nickname, public ID, date of birth, status and existing three-dot menu remain available. Desktop table is unchanged.
- Avatars reuse ProfileAvatar. Existing avatar data is rendered when supplied by the record; otherwise initials identify the person. No per-row profile lookup or new API call is added just to obtain an image. Current list endpoints do not consistently include custom avatar choices, so initials are the supported fallback for those responses.
- Schedule viewer: mobile full-screen dialog with an explicit close button, month selector, calendar highlighting scheduled dates, and compact date/weekday/time rows. All dates can also be viewed grouped by month; equal-time sessions share the time caption, while differing times remain attached to each date. The same already-loaded schedule data powers every view; no extra fetch, timer or polling. Desktop opens the same calendar/month/list content in a regular 760px popup with a close icon and footer button; mobile keeps the full-screen viewer.
- Tree mode only, on both desktop and mobile: each file is a compact row with checkbox, one-line filename (full name in tooltip), type/public code/size, uploader and existing information menu. Preview, selection, branch expansion, nesting, file paging and folder/grid mode are unchanged. Figma icon roles use the existing MUI library; no temporary asset URLs, new fonts or icon dependency are added.

Styles use existing MUI palette, spacing, breakpoints and components. No backend, migration, storage configuration or data change is needed.

Validation includes staged/cancelled filters with no requests before Apply, mobile row navigation versus checkbox selection, roster menu behavior, tree row bounds/selection on mobile and desktop, and month/all-date schedule navigation on mobile and desktop, including desktop popup bounds. Screenshots are generated by the browser tests under test-results/.
